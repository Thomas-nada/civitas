## Vote: Yes

I am voting Yes on the 600,000 ada Mesh SDK Maintenance 2026 withdrawal. This is maintenance funding for a free, open-source toolkit that 889 GitHub projects build on, priced from a measured reference year, paid quarter by quarter against public reports, with unspent funds returned to the treasury and a 3-of-4 multisig wallet on every payment. This is the kind of ask the treasury should be getting more of: a fixed ada amount, checkable output, and a refund clause.

The HOSKY Cardano First framework reads strongly across Adoption, Governance Transparency and Economic Sustainability.

## Pillar analysis

### Adoption (lead pillar)

Mesh is plumbing developers actually use. Downloads of the main package more than doubled in 2026: 311,234 from the start of January to early November, against 127,746 in the same months of 2025. The dependent projects include Aiken, the Cardano Foundation developer portal, governance tooling used by Intersect, Masumi, NMKR, Socious and SwapKit. When Cardano changes under the hood, apps built on Mesh keep working because this crew keeps up: every 2026 protocol change, including the protocol version 11 hard fork, shipped in a tested Mesh release before it reached mainnet. In May, a fee-calculation change on the test networks broke Mesh-built apps; the fix landed before mainnet, and the issue threads are public.

The 2026 feature list matters beyond maintenance: full on-chain governance support in a stable release (all seven governance action types, voting, registration and delegation), payments for websites and APIs (x402), programmable tokens, local smart-contract testing and new data providers. Tooling that makes it easier to build on Cardano is the cheapest adoption spending available to the treasury, and this toolkit's usage is counted in public npm and GitHub numbers, not booth contacts.

### Governance Transparency

Every claim in this proposal links to a public pull request, release or download statistic, and the crew publishes a running dashboard where quarterly reports list releases, protocol changes, fixed issues and every payment from the wallet with transaction links. The Catalyst record is complete: the F10 through F14 proposals, about 2.1 million ada in total, all delivered and closed. The reporting structure proposed from 2027 is the right shape: one proposal per year, quarterly public reports, and payout only after each quarter's report.

This is measurable in a way an events program is not. An SDK's output shows up in releases, issue trackers and download counts that anyone can check without trusting the proposer's own summary.

### Economic Sustainability

The ask is 600,000 ada, 50,000 a month, for five maintainers and a contributor pool, sized from a year of actual work rather than a projection. There is no dollar-denominated budget converted at an assumed exchange rate; the amount is fixed in ada, so the treasury's exposure is exactly what is printed. Unspent funds go back: declined shares within 30 days, and from 2027 anything unspent each quarter. Payments require 3 of 4 team signatures.

At 2.4 percent of the events renewal sitting in the same voting window, the return per ada is not close. This proposal keeps the tool layer under hundreds of live projects working.

### Decentralization (mixed)

The honest concern is concentration: a small team carries a toolkit with 889 dependents, and a funded core team can crowd out other contributors. The mitigation is that everything is open source, 14 contributors merged pull requests this year, and the toolkit supports multiple data providers rather than one. The bus factor is real and I accept it knowingly; the alternative, an unmaintained core SDK, is worse.

## Risks I'm accepting with this Yes

### Paying for work already done

The reference-year model funds 2026 work at the end of 2026. I accept that back-pay framing once, because the numbers it produced are exactly what makes the ask credible. From 2027 the pattern must be funding ahead, quarter by quarter.

### A yearly funding precedent

Approving this bootstraps a recurring category: core maintenance asks submitted each year. Each year still needs a fresh vote with fresh reporting, so the gate stays in DRep hands, but the constituency for renewal will only grow. I accept that precedent for tools with this level of public usage evidence.

### Key-person dependency

A few dedicated people carry the toolkit. If they stop, 889 dependents inherit the problem. The open-source license and public history make a handover possible, not painless.

## Decision

The same voting window asks for 25 million ada of conference floor space and 600,000 ada to keep the tool layer under hundreds of Cardano applications working, with receipts attached to every claim. That is not a hard call. **Yes.**
